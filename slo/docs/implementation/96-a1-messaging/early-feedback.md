- **M4:** `queue.py` concrete methods are ellipses and there is no queue test file. Implement authorized mutex/priority/FIFO/condition/seal behavior using real MessageStore plus an injected synchronous authority check. This can be tested entirely within the authorized module. Production session capability/registration remains unwired, explicitly excluded here.
- **M5:** `delivery.py` is the prescribed run-state dataclass plus a Protocol, **not a missing concrete session service that belongs in this file**. Protocol ellipses are legitimate. Boundary slot validation exists in `dao.py`; retry cache/application/advancement are assigned by H to session and agent. A module contract test can prove records/local state behavior, but cannot close those assigned runtime behaviors without excluded edits. Do not create a competing delivery executor to inflate M5 completion.
- **M6 — specific public-contract dependency:** `LocalSessionMessagingClient` is an actual skeleton. H requires session-tracked submit tasks, shared close joins, admission_seconds from session configuration, and session authority/lifecycle methods. Searches of current `sessions/{dao,service}.py` find none of `messaging_limits`, `start_messaging`, `admit_message`, `get_message_receipt`; the spec supplies no existing shared-task adoption API. Its concrete `SloAgentSession` signature therefore cannot be fully fulfilled/production-verified under a strict module-only edit boundary. A narrow module-owned consumer Protocol plus injected recording session stub can prove client deadlines/target/error/close mechanics and document the later task-ownership seam; that is **adapter-only evidence**, not session-owned admission. Keep full M6 blocked at that exact integration edge, or obtain authorization later—never silently add session edits or use getattr fallbacks/implicit startup.

Actual append-once, normalized replay proof, history compaction selection and projection are absent and remain integration prerequisites, not reasons to block useful M2 work. `mark_history_committed(message_id)` is the session’s assertion after append, not a claim that MessageStore independently inspects JSONL.

Local UI safety, slash recovery commands, legacy provenance bridge, finite headless completion and application authority are user-excluded now but still required by full A.1.
