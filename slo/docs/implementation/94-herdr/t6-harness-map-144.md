- `open`, `io.open`, `Path.open/write_text/write_bytes`, tempfile writable allocations: CPython `open` audit flags identify writes/create/truncate/append. Unknown ordinary read/import paths are allowed; this is essential for trusted Python/packages/source imports. No blanket deny of import/read audit events.
- Raw `os.open`: wrapper accounts for dir_fd before syscall and audit. Integer-file writable construction is checked through descriptor identity. No writable host FD is intentionally handed into entry; stdin is not a general mutation capability.
- `os.write/writev/pwrite/pwritev/ftruncate/fchmod/fchown`: installed wrapper table; used raw os.write proven, ftruncate/fchmod negative cases present. pwrite/writev/fchown are not invoked by this entry, so their existence does not justify claiming an executed all-branch matrix. `write/writev` stdio exemption binds captured identity only and grants no truncate/chmod permission.
- mkdir/remove(unlink)/rmdir/chmod/chown/utime/truncate/xattr and rename/replace/link have named audit handling. Relative directory capabilities are resolved; both move/link endpoints checked. Symlink creation always refuses. Existing actual eight-operation installed test proves write_text/touch/chmod/unlink/both replace directions/mkdir/rmdir. Metadata extras and dir_fd mutation tables are policy-level tests, correctly distinguished from actual syscall evidence.
- Buffered file-object writes are **not** intercepted per `.write()` by monkeypatching os.write. Their safety comes from audited acquisition of the newly owned path/FD, plus exclusive fixture ownership. fsync/flush/close are not generic path mutation authorization APIs: they operate on that acquired handle; no separate fsync sandbox claimed. Descriptor duplication or a malicious retained C file object is outside this bounded fixture capability.
- Guard rejects outside/traversal/symlink/special/multiply-linked mutation targets; opened descriptor checks reject changed/deleted paths and wrong type/link/identity. Missing or unreadable path evidence fails rather than grants permission. Capture adds registered identity and exact requested pathname, stronger than generic containment.
- Unsupported execution routes explicitly covered by the contract (exec/spawn/fork/forkpty/system) deny. Unregistered subprocesses deny. Network connect/connect_ex/bind deny; no real network probe performed. No arbitrary `event.startswith('os.')` wildcard is proposed: harmless imports, reads, metadata inspection and supported bookkeeping must remain available.
- Not a malicious-Python sandbox: trusted source can call native extensions, alter Python objects or race the filesystem; same-inode content rewriting, arbitrary close/reuse before initial fstat, hostile root replacement, escaped process groups and atomic check/use confinement are not promised. New actual writer/execution paths require fresh mapping before admission, rather than silently inheriting a universal capability claim.
