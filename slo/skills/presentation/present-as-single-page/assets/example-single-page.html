The order the source actually runs

Your four-step mental model holds up; the one refinement is that on_mount fires per widget, not once at the end.

#StepWhen
1SloTUI.__init__Sync construction — no DOM yet. Registers themes, stores session, sets widget handles to None.
2events.ComposeDispatched by the run loop first; drives compose().
3compose()Yields the tree; each yield constructs a child and mounts it.
4child.on_mount ×NEach child mounts recursively, leaf-first, posting its own Mount.
5events.Mount → on_mountApp's own on_mount — only after the subtree is live and queryable.

Why it feels inverted: a child's on_mount runs before the app's, because children finish mounting first. That's exactly why on_mount is the safe place to query the DOM.

Compose is dispatched before Mount

The ordering is fixed in App._process_messages, so on_mount always runs after the tree is built — verified against the installed Textual 0.89.1.

textual/app.py · run_process_messages() · ~L3073
# the app's own mount sequence, in order:
await self._dispatch_message(events.Compose())   # → compose() builds children
await self._dispatch_message(events.Resize.from_dimensions(...))
self.stylesheet.apply(self)
await self._dispatch_message(events.Mount())     # → on_mount() runs last

Inside on_mount() — order is load-bearing

By here the whole tree exists, so the method orchestrates a precise startup (app.py:341):

  1. _hydrate_transcript_from_history() — replay persisted events into the same widgets a live run uses.
  2. _maybe_render_startup_notice() — one-time tip line for new sessions.
  3. session.subscribe(handler=…) — subscribe the live renderer, strictly after hydration.
  4. _refresh_title_bar() / _refresh_usage_status_bar() — paint chrome now that widgets are queryable.
  5. self._input.focus() — hand the user a ready cursor.
  6. push AuthenticationScreen if no credential for the active model.

Why 1 before 3 (sub-spec 05.e §7.2): hydrate the replay tail before subscribing live events, so a fresh prompt's events can't interleave with the historical ones.

The reliable rule

__init__

Stores config. No DOM. Don't query widgets.

compose

Builds and yields the widget tree.

on_mount

Fires per-widget once it's in the DOM. Wire up here.
