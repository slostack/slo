# Slo Skills Index

This file lists the bundled skills available to the slo agent.
Start with `skills/engineering/engineering-routing/SKILL.md` for layered selection.
Installed user skills/workflows also appear in the runtime manifest; same-name
user entries override bundled entries. This index is not the complete installed catalog. The agent reads this
index on demand (via the `read` tool) when a task starts; when a task matches
a skill's description and routing hints, the agent then reads that skill's
`SKILL.md` and follows its instructions.

Each skill below is a markdown file with YAML frontmatter (`name`,
`description`, `when_to_use`, `group`, `kind`) plus an instructional body.
The index is grouped into **Workflows** and **Individual Skills**, then
split by category.

> **Note:** this file is regenerated by `make build-skill-index` from the
> current `skills/**/SKILL.md` tree. Edit the SKILL.md files
> (not this index) when adding or revising a skill, then re-run the
> regenerator.

### Orchestration
- **headless-orchestration** — Launch a named Slo workflow as a DETACHED headless orchestrator process — triggered only when the user adds an explicit detach qualifier ("headless" / "detached" / "independent" applied to a dynamic-workflows request or a named workflow, or detach wording "in the background" / "without blocking"). An unqualified "dynamic workflows" request runs in-session via spawn_sub_agents and does NOT trigger this skill. Sets the required timeout env vars, selects models per phase, dispatches phases serially or in parallel, and monitors child agents until the orchestrator reaches a terminal state. A detached orchestrator never calls launch_workflow. When to use: Use when the user explicitly asks to run a workflow with a detach qualifier — "headless dynamic workflows", "detached dynamic workflows", "independent dynamic workflows", "run the code-test-review workflow detached", or detach wording like "in the background" / "without blocking" applied to a workflow request. Do NOT load this skill for an unqualified "dynamic workflows" or "dyanmic workflows" phrase (no detach qualifier) — that runs in-session via spawn_sub_agents. Also load this skill when the user explicitly asks to execute a workflow using the headless runner (slo run --orchestrator) from a shell or CI pipeline. Path: `skills/orchestration/headless-orchestration/SKILL.md`
- **orchestrator** — Gateway workflow that decides which skill or workflow to load next for the current task. Routes "dynamic workflows" / "dyanmic workflows" (no detach qualifier) to in-session multi-agent orchestration via spawn_sub_agents; routes a detach-qualified request ("headless" / "detached" / "independent" dynamic workflows, or a named workflow with "in the background" / "without blocking") to the headless-orchestration skill via launch_workflow. A detached orchestrator never calls launch_workflow. When to use: Use at the start or end of a turn when you need to route the task into the right Slo workflow, category, or individual skill. Path: `skills/orchestration/orchestrator/SKILL.md`
