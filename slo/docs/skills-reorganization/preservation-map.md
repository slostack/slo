## Limitations / follow-up review boundaries

- The original installed optional-stack recipes remain rich, but many snippets are illustrative fragments using application-specific types. Only explicitly standalone new Go examples were compiled; no claim is made that every Gin/GORM/Temporal/asynq/ClickHouse snippet compiles as a standalone program.
- Core contradictions above were reconciled. The much larger imported library still warrants stack-specific generated-feature evaluations for semantic consistency and quality; source/heading preservation cannot certify every normative sentence has exactly one owner.
- User-installed Go and TypeScript guidance remains untouched. Canonical Go names avoid legacy collisions; installed TypeScript names retain ordinary user override semantics. The router explains the source distinction.
- No external project instruction files were rewritten. Stable forwarding paths and stable workflow entry points protect existing references; unknown external references cannot be exhaustively verified.
- No live-provider multi-language generation benchmark was run. Routing scenarios are intended-selection contracts and structural checks, not observed model selection.
